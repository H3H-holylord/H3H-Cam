# H3H Cam 4.0.4 — задержка под нагрузкой игры

3 октября 2026. Обновление Windows-клиента; Android остаётся 4.0.3 / versionCode 16.

## Что исправлено

Ранее один цикл читал rawvideo из FFmpeg, выполнял эффекты и отправлял кадр в Spout/виртуальную камеру. Медленный вывод останавливал чтение и мог создавать очередь старых кадров в pipe и декодере. Это затрагивало USB и Wi-Fi.

Теперь чтение и обработка независимы. В ожидании вывода хранится только последний полностью декодированный кадр. Используются три переиспользуемых буфера; устаревшие ожидающие кадры пропускаются. Буфер, который уже обрабатывается, не перезаписывается. Сжатые H.264/HEVC кадры не отбрасываются этим механизмом, поэтому зависимости декодера сохраняются. Такой же механизм применён к предпросмотру. Входной буфер named pipe уменьшен с 32 MiB до 256 KiB.

В строке Direct/Spout появились фактический FPS выхода и число пропущенных устаревших кадров. При перегрузке возможна меньшая плавность, но очередь ожидающих обработку кадров не растёт. Показатель FPS приёма от телефона и FPS выхода могут различаться.

## Проверки

- Регрессионный тест блокирует вывод первого кадра и отправляет ещё 1200 кадров через настоящий named pipe с фрагментированными записями. После разблокировки вывод получает только первый и последний кадр: 1199 устаревших пропущены. Проверены целостность занятого буфера, обрыв посреди кадра и завершение после ошибки потребителя.
- Полный набор unit-проверок Windows прошёл.
- Аппаратный тест SM-N960N по USB: 1080p60 HEVC, 32 Mbps, 30 секунд, одновременно предпросмотр, Spout и виртуальная камера. FPS превью 59.97, FPS выхода 59.97, P99 интервала превью 23.1 мс, максимальный интервал 33.4 мс, ошибок опорных кадров 0. Счётчик устаревших кадров к последней телеметрии: 42 (включая запуск).
- Результаты: `audit-latency-4.0.4/usb60/pacing.json`, тесты и логи рядом.

Это проверка очереди при искусственной остановке и короткий USB-тест, а не измерение полной задержки камера→запись под конкретной игрой. Очереди внутри драйвера GPU/FFmpeg и задержка OBS отдельно не измерены. При следующем игровом тесте сравните FPS выхода и счётчик пропусков. Если задержка остаётся, нужны название игры и фрагмент записи с рассинхронизацией для дальнейшей проверки.

## Воспроизведение

```powershell
dotnet run --project tests -c Release -- unit audit-latency-4.0.4/unit
dotnet run --project tests -c Release -- pacing-test audit-latency-4.0.4/usb60 60 hevc 32 30 0 usb
```

После аппаратного теста сохранённые настройки восстанавливаются. Установщик не меняет пользовательский битрейт, FPS, зум и параметры OBS.
