# Исправление вылета после запуска

Windows **4.0.9**, Android **4.0.4 без изменений**. Проверка 2026-10-10.

Поступило сообщение: «H3H Cam через секунд 5 вылетает на ПК». Версия приложения, Windows и журнал с этого ПК пока не получены. Ниже описан воспроизведённый дефект с похожим сценарием; подтверждение исправления у автора сообщения требуется отдельно.

## Воспроизведённая причина

При первом запуске с чистыми настройками выбран USB Direct. Автоматический поиск создавал libusb-контекст и списки устройств. Объекты перечисленных USB-устройств не освобождались явно. Контекст закрывался, а устройства могли оставаться до очередной сборки мусора. Их финализаторы вызывали `libusb_unref_device` после завершения контекста и аварийно завершали процесс.

Проверка версии 4.0.8: USB-поиск без переключения телефона, закрытие контроллера, `GC.Collect()` и ожидание финализаторов. Уже первый цикл завершился с **0xC0000005** (−1073741819):

```text
System.AccessViolationException
LibUsbDotNet.NativeMethods.UnrefDevice
LibUsbDotNet.Device.ReleaseHandle
System.Runtime.InteropServices.SafeHandle.Finalize
```

Это ошибка доступа к нативной памяти: обычный `catch (Exception)` в окне не восстанавливает процесс после такого сбоя. Время до вылета зависит от момента сборки мусора, поэтому оно не обязано быть ровно пять секунд.

Контракт владения коллекциями и клонирования описан в [точной ревизии LibUsbDotNet](https://github.com/LibUsbDotNet/LibUsbDotNet/blob/a89bc81569327840e98a2c30207e5b74bbc97b3a/src/LibUsbDotNet/LibUsb/UsbContext.cs).

## Исправление

- Поиск accessory использует `context.Find`: результат — отдельный принадлежащий контроллеру объект, временная коллекция освобождается при живом контексте.
- Коллекция кандидатов для AOA-переключения закрывается через `using`, включая ранний выход и отмену.
- Удерживаемое устройство освобождается до контекста; ошибка открытия тоже освобождает принадлежащий контроллеру объект.
- Автоматический поиск при открытии окна проверяет уже активный USB Direct без команды переключения режима. Кнопки «НАЙТИ» и «СТАРТ» сохраняют обычное подключение.
- Параметр `--safe-mode` отключает автоматические поиск и старт на текущую сессию, не переписывая настройки.
- Журнал запуска содержит версию клиента, Windows, .NET и архитектуру. Необработанные фоновые исключения также записываются.

## Проверки

После исправления **30 циклов поиск → dispose → принудительный GC** завершились успешно, в том числе с реальными USB-устройствами на локальном ПК. Unit-тесты проходят. Это целевой тест времени жизни нативных объектов, не проверка подключения камеры через WinUSB на всех моделях телефонов.

Тесты полноценного EXE запускают отдельные процессы с изолированными настройками и журналами: чистый профиль, отсутствие DLL libusb, автозапуск с отсутствующим ADB и безопасный режим. Каждый процесс наблюдается более 12 секунд и затем завершается тестовым помощником. Пользовательские настройки и рабочий поток не используются.

```powershell
dotnet run --project tests -c Release -- usb-probe-stress
dotnet run --project tests -c Release -- startup-smoke "dist/H3HCam Receiver.exe" test-results/startup
```

Эти проверки выполнены на локальном Windows-ПК, а не на ПК автора сообщения и не на всех версиях Windows. Тест USB-поиска также включён в GitHub Actions.

## Что передать автору сообщения

Распакуйте новый [Windows 4.0.9 ZIP](https://github.com/H3H-holylord/H3H-Cam/releases/tag/v4.0.9) в отдельную папку целиком. APK обновлять не требуется. Если вылет повторяется, попробуйте запуск из PowerShell в папке клиента:

```powershell
& '.\H3HCam Receiver.exe' --safe-mode
```

Если безопасный запуск работает, сообщите, какой транспорт выбран и возникает ли сбой после «НАЙТИ» или «СТАРТ».

Скрипт `Collect-Diagnostics.ps1` входит в Windows ZIP. После вылета он собирает версию Windows, GPU/драйвер, версию/хеш EXE, последние события Windows об ошибке H3H Cam и хвост журнала приложения:

```powershell
.\Collect-Diagnostics.ps1
```

Вариант с наблюдением за новым запуском (сначала закройте работающий H3H Cam):

```powershell
.\Collect-Diagnostics.ps1 -Launch
.\Collect-Diagnostics.ps1 -Launch -SafeMode
```

Наблюдение длится до 30 секунд. При вылете записываются время и код завершения. Живое приложение остаётся открытым; скрипт не сбрасывает настройки и не устанавливает драйверы.

Отчёт сохраняется в `%LOCALAPPDATA%\H3HCam\diagnostics`. Журнал приложения находится в `%LOCALAPPDATA%\H3HCam\logs`. Перед публикацией просмотрите отчёт: журнал может содержать локальные пути, адреса и идентификаторы устройства. Скрипт ничего не отправляет в сеть и не создаёт дамп памяти.

Для изолированных QA-проверок можно задать дочернему процессу абсолютный `H3HCAM_DATA_DIR`; тогда настройки и логи используют эту папку, а миграция старого профиля отключается. В обычном запуске расположение профиля сохраняется.
