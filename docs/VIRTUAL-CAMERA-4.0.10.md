# Виртуальная камера — исправление 4.0.10

Участник форума подтвердил, что после 4.0.9 клиент работает, но виртуальной камеры нет даже после включения галочек. Полученная конфигурация: i5-12400F, RTX 3060 12 GB, Windows 11 Pro x64 28000.1199 (Canary). Его журнал и результат проверки 4.0.10 ещё не получены.

## Причина в клиенте и упаковке

- Галочка включала вывод кадров, но не устанавливала DirectShow-камеру. Установка находилась в отдельной вкладке и отсутствовала в простом режиме.
- Публичный ZIP не содержал модулей OBS Virtual Camera. Наличие рабочего Spout/предпросмотра не означало наличия зарегистрированной веб-камеры.
- Проверка установки принимала наличие COM-ключа за готовность, даже если DLL исчезла или устройство отсутствовало в категории видеокамер. Регистрация могла указывать на переносимую папку.
- Статус обещал Media Foundation только по наличию API в Windows. Экспериментальный код использовал незарегистрированный CLSID источника, не реализовывал IMFMediaSource и не вызывал IMFVirtualCamera::Start. Эта заглушка удалена. [Требования Microsoft к источнику](https://learn.microsoft.com/en-us/windows/win32/api/mfvirtualcamera/nf-mfvirtualcamera-mfcreatevirtualcamera).

## Поведение 4.0.10

Windows ZIP содержит неизменённые официальные OBS 32.2.2 DLL для 64- и 32-битных потребителей. Галочка и первый старт видеовывода выполняют регистрацию для текущего пользователя без UAC. DLL сохраняются в `%LOCALAPPDATA%\H3HCam\virtualcam` по хэшу, поэтому перенос папки клиента не ломает камеру. Рабочая существующая регистрация OBS используется повторно. Старые регистрации H3H Cam с путём в переносимую папку мигрируют.

Проверяются сервер COM, существование и архитектура DLL, контрольная сумма сохранённой копии, запись устройства в категории захвата и описание форматов. Повреждённая сохранённая копия восстанавливается в новом каталоге без замены DLL, которую могло загрузить другое приложение. Настоящее имя камеры и кнопка установки/восстановления видны в обоих режимах интерфейса. Ошибки установки сообщаются явно. Установка камеры не требует полного OBS Studio.

1. Полностью распакуйте Windows 4.0.10 ZIP, включая `tools/virtualcam`.
2. Включите «Виртуальная камера» и запустите поток.
3. Перезапустите приложение видеозвонков или обновите список устройств. Выберите имя, указанное клиентом: `H3H Cam` или `OBS Virtual Camera`, если используется ранее установленная OBS-камера.
4. Не включайте одновременно «Запустить виртуальную камеру» в OBS: у этих выходов общая память. Для игрового стрима через Spout2 виртуальная камера нужна только при использовании её в другом приложении.

Для OBS через обычное устройство захвата выберите камеру, фактические разрешение/FPS потока и отключите буферизацию. Доступность камеры в конкретном приложении зависит также от его поддержки DirectShow и настроек доступа Windows. Новая самостоятельная камера Media Foundation этим релизом не добавляется.

## Проверка

- Windows unit tests: независимые приватные ветки реестра для x64/x86; чистая установка, отсутствующая категория, повреждённая/чужой архитектуры DLL, исчезнувший путь и перенос исходной папки. Тесты не регистрируют камеру в рабочем профиле пользователя.
- Реальная DLL x64 активирует IBaseFilter. Модули обеих архитектур совпали побайтово с официальным Windows ZIP OBS 32.2.2.
- FFmpeg как отдельный DirectShow-потребитель получил 30 NV12 кадров 1920×1080 с запросом 60 FPS; все байты совпали с тестовым источником, включая контроль ориентации по углам.
- Это проверка регистрации и захвата тестовых кадров на локальном ПК. Работа на ПК участника форума, конкретные приложения видеозвонков и задержка под игровой нагрузкой требуют отдельного подтверждения.

APK остаётся 4.0.4. Исходники OBS-модулей и лицензия включены в релиз.
