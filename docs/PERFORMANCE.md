# Нагрузка CPU и настройка для стримов

Windows-клиент 4.0.6 устраняет лишнюю работу, сохраняя настройки качества и выходы камеры.

## Что изменено

- При BGRA-выводе Spout2 предпросмотр берёт кадр из того же декодера. Отдельный FFmpeg остаётся резервным путём для NV12-вывода без Spout и для одного предпросмотра.
- Скрытый или свёрнутый предпросмотр не масштабирует кадры и не обновляет WPF. Камера для OBS и других приложений продолжает работать. Снимок из трея кратко запрашивает свежий кадр.
- Цветовые профили Clean/Warm/Cold и независимые коррекции каналов при нейтральной насыщенности используют кэшированные таблицы. Результат побайтово совпадает с прежними формулами. Смешивающие каналы профили и насыщенность сохраняют прежний расчёт.
- BGRA → NV12 использует AVX2 для яркости, совместимый скалярный резервный путь и не более двух работников. Округление/среднее цветности сохранены.
- Кадр виртуальной камеры копируется в общую память одним блоком, с сохранением протокола публикации трёх слотов OBS.
- Очередь по-прежнему хранит последний готовый кадр и пропускает устаревшие при перегрузке.

## Локальные измерения 2026-10-04

Проверка на компьютере с 16 логическими процессорами: USB ADB, 1920×1080, 30 FPS, HEVC 20 Мбит/с, профиль Clean, включённые Spout2 и виртуальная камера, окно клиента в трее. Значения — доля всей мощности CPU, сумма клиента и его FFmpeg. OBS не вёл эфир/запись; игровой нагрузки не было. Замеры длительностью 10–15 секунд, без профилировщика во время итогового замера.

| Процесс | До (4.0.5) | После (4.0.6) |
|---|---:|---:|
| Клиент | 10,46% | 2,70% |
| Основной FFmpeg | 2,42% | 1,91% |
| Отдельный FFmpeg предпросмотра | 1,24% | отсутствует |
| Сумма | **14,12%** | **4,61%** |

Снижение около **67%** в этой конфигурации. Это не гарантия результата на другом ПК, при AI-эффектах или во время Hunt.

Проверка USB-потока с объединённым декодером: 1080p30 HEVC20 — 29,98 FPS; 1080p60 HEVC32 — 59,91 FPS, P99 интервала предпросмотра 22,55 мс, ошибок опорных кадров 0. Это интервалы доставки кадров, а не измерение задержки «объектив → монитор».

Отдельные микротесты 1080p подтвердили побайтовое совпадение NV12 и цвета. CPU-время Clean: 36,63 → 2,43 мс/кадр; BGRA→NV12: 19,79 → 3,47 мс/кадр; копирование общей памяти: 1,74 → 0,17 мс/кадр. Время CPU включает все работники и отличается от времени одного кадра на часах.

## Использование

Для OBS используйте Spout2 Capture. Во время игры сворачивайте клиент в трей или выключайте его предпросмотр. Это не меняет разрешение/FPS видео в OBS. AI-фон, сглаживание кожи и 4K-апскейл требуют дополнительной обработки; включайте их при необходимости. 60 FPS сохраняйте, когда камера поддерживает выбранный режим.

## Следующий шаг архитектуры

Телефон уже передаёт кадры Camera2/Surface в аппаратный MediaCodec. На Windows текущий FFmpeg всё ещё выгружает декодированные пиксели в системную память, после чего Spout загружает их обратно в GPU. Следующий крупный шаг — аппаратный декодер с сохранением D3D11-текстур, GPU-поворотом/цветом и прямым Spout-выводом. Он ещё не реализован: потребуется проверить совместимость кодеков, видеокарт и виртуальной камеры, а также влияние конкуренции с игрой за GPU.

## Воспроизведение проверок

```powershell
dotnet run --project tests -c Release -- performance-test
dotnet run --project tests -c Release -- shared-preview-test
dotnet run --project tests -c Release -- pacing-test test-results/usb60 60 hevc 32 20 0 usb
```

Последние две команды запускают камеру подключённого телефона. Закройте рабочий клиент перед ними. Аппаратные тесты возвращают сохранённые настройки после завершения. Для сравнения CPU измеряйте одинаковые разрешение/FPS/кодек/битрейт/эффекты и суммируйте CPU клиента и дочерних FFmpeg; отдельно фиксируйте, виден ли предпросмотр.
