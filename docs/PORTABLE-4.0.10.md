# Полный Portable 4.0.10

Рекомендуемый файл для нового пользователя: **H3H-Cam-4.0.10-Portable.zip**. Он включает Windows-клиент 4.0.10 и Android 4.0.4, FFmpeg/FFplay 9.0.1, ADB 37.0.1 с необходимыми DLL, libusb, официальные модули виртуальной камеры x64/x86 и AI-модель u2netp.onnx. Сам Windows-клиент и APK совпадают с ранее проверенным релизом; изменение касается комплектации и инструкции.

Всё распаковывается в одну папку. Устанавливать .NET, FFmpeg, FFplay, ADB, задавать PATH или искать модель отдельно не нужно. Клиент при пустых полях путей ищет утилиты в своей папке `tools`; модель находится в `models`. Сохраняйте эти папки рядом с EXE. Пользовательские настройки и логи хранятся отдельно в AppData и не входят в архив.

## Первый запуск

1. Распакуйте **весь архив** и откройте `README.txt` или [быстрый старт](QUICKSTART.md).
2. Запустите EXE. Установите APK на телефон вручную либо через `Установить на телефон.cmd` после включения USB-отладки и подтверждения доступа. Установщик обновляет приложение на одном разрешённом устройстве, не удаляет приложения и не выбирает телефон из нескольких автоматически.
3. Откройте приложение телефона, разрешите камеру. Выберите **USB · через ADB → НАЙТИ → СТАРТ** в Windows-клиенте.
4. Включите виртуальную камеру. В OBS используйте обычное **Устройство захвата видео**, в видеозвонках выберите имя камеры из статуса клиента. Spout2 — дополнительный вариант для пользователей с установленным плагином.

Portable не заменяет разрешения Android, кабель для данных и USB-драйвер производителя. Для USB Direct нужны поддержка Android Accessory и WinUSB; это другой способ подключения. OBS/Discord/Zoom не включаются в архив. 60 FPS, разрешения и набор камер зависят от телефона.

## Контроль состава

`Create-Portable-Package.ps1` проверяет release EXE/APK, закреплённые SHA256 утилит, модели и обязательные DLL. Отсутствующий компонент останавливает упаковку. `COMPONENTS.json` сохраняет версии, хэши и источники; `SHA256SUMS.txt` внутри ZIP проверяет все включённые файлы. Лицензии и upstream notices находятся в `licenses`.

Модель сопоставлена по SHA256 с опубликованным ONNX из rembg; FFmpeg и ADB побайтно сопоставлены с официальными пакетами. Облегчённый Windows ZIP оставлен отдельным вариантом для существующей установки и ясно обозначен как требующий внешних утилит.

## Проверка

Проверка выполняется на тестовой распаковке в пути с пробелами и кириллицей, с пустым профилем настроек и PATH только из Windows System32. Тестовый `ToolProbe` собирается отдельно с **исходным ToolPaths.cs клиента** и должен найти все три EXE именно в `tools` этой распаковки. Он проверяет версии/хэши и декодирует 60 кадров каждого из H.264 и HEVC, включая поворот, масштабирование и NV12. Затем отдельно проверяется запуск самого self-contained клиента с пустыми настройками.

Это изолированный локальный тест комплектации на имеющемся PC, а не тест новой установки Windows или универсальности драйверов телефона. Полный пакет не требует предварительно установленного .NET для запуска клиента; SDK нужен только разработчику для сборки тестового probe.

Результат: все три утилиты найдены в распакованном `tools`; H.264 и HEVC — по 60 декодированных кадров с проверкой объёма NV12; FFplay воспроизвёл тестовое видео с виртуальным SDL-дисплеем без окна на рабочем столе. Сам релизный EXE работал более 15 секунд с новым профилем, без необработанного исключения. Файл установки APK проверен на макетах ADB: пустой список, `unauthorized`, два устройства, один разрешённый телефон и отказ установки. Только два последних сценария отправляют команду `install -r` нужному serial; тесты не обращаются к реальному телефону.
