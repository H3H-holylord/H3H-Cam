# Проверка обновления Antigravity

Windows **4.0.8**, Android **4.0.4**, versionCode **17**. Проверка 2026-10-09 относительно опубликованной 4.0.7 и локальных изменений Antigravity. Параметры камеры пользователя сохраняются.

## Почему изображение перевернулось

FFmpeg уже выполнял поворот и зеркалирование из настроек. Новый NV12-путь повторно передавал те же параметры GPU-шейдеру Spout. При выбранном повороте 180° два поворота давали 360°: необходимая коррекция положения телефона исчезала. Предпросмотр и виртуальная камера использовали результат FFmpeg, поэтому могли отличаться от OBS.

Теперь FFmpeg выполняет ориентацию один раз для всех выходов, а GPU получает уже преобразованный кадр с rotation=0 и mirror=false. Не требуется компенсировать ошибку дополнительным переворотом источника OBS.

## Что сохранено и исправлено

| Изменение Antigravity | Результат проверки и итог |
|---|---|
| Общий предпросмотр для NV12 и BGRA | Сохранён. Для Spout/виртуальной камеры и предпросмотра достаточно одного декодера. Скрытый предпросмотр спит. |
| NV12 → GPU-цвет/масштабирование → Spout | Сохранён для совместимых настроек. Raw-поток остаётся в памяти CPU и загружается в GPU; это не zero-copy. |
| Принудительный NV12 для всех эффектов | Исправлен выбор формата: RGB используется там, где нужны совместимые цвет/WB для обоих выходов или альфа-канал Spout. NV12 не хранит прозрачность. |
| Новые GPU-профили цвета | Восстановлены все шесть профилей и формулы RGB-контракта, включая Teal/Orange и Noir. Учтены WB, яркость, контраст и насыщенность. |
| Интерпретация YUV без метаданных | В raw NV12 явно задаётся limited BT.601 через FFmpeg. Входной BT.709 преобразуется до удаления метаданных. Конвертеры CPU/GPU получают одну цветовую модель. |
| NV12-масштабирование для виртуальной камеры | Сохранено. Добавлены проверки чётных размеров, полных и раздельных буферов; исправлена гонка кэша таблиц; параллелизм ограничен двумя работниками. |
| GPU-очередь 4 кадра и цикл ожидания | Возвращены две незавершённые операции и проверка готовности без цикла ожидания. Занятая очередь пропускает кадр, не накапливая старые кадры. |
| Очереди отправки Android 6 → 24 | Возвращён предел 6. Очередь из 24 кадров могла добавлять до 400 мс при 60 FPS или 800 мс при 30 FPS. Сам предел не означает постоянную задержку такого размера. |
| Отключение UDP-пейсинга | Возвращено прежнее сглаживание пакетов до 20 Мбит/с; более высокие битрейты остаются без этого ограничения. |
| Отключение переупорядочивания RTP | Возвращено окно 256 пакетов с max_delay 30 мс для обработки Wi-Fi-пакетов, пришедших не по порядку. |
| Искусственное выравнивание EGL timestamp | Сохраняется реальное время сенсора. Только отсутствующий/повторный/обратный timestamp заменяется минимальным монотонным шагом, без принудительной имитации 60 FPS. |
| Удаление регулярных записей областей face-focus | Сохранено: Samsung backend больше не переписывает параметры фокуса при каждом достаточно большом перемещении лица. Continuous-video focus, обнаружение лиц и явный tap-to-focus остаются. Устранение аппаратных остановок ISP отдельно не измерялось. |

При изменении настроек, требующем другого raw-формата, заменяется декодер Windows. Телефон продолжает передавать поток. Настройки интерфейса и сцены OBS не переопределяются.

Матрицы и диапазоны scale описаны в [документации FFmpeg](https://ffmpeg.org/ffmpeg-filters.html#scale). Ограничение очереди использует [D3D11 GetData](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-getdata).

## Проверки

- На исходной версии Antigravity тест с четырьмя различимыми углами воспроизводит ошибку зеркалирования: GPU и ожидаемая ориентация расходятся. Исправленная версия проходит повороты 0/90/180/270° с зеркалированием и без него, для реальных FFmpeg, GPU-текстуры и общего предпросмотра.
- Отдельный красный поток с метаданными BT.709 сохраняет цвет после преобразования в raw NV12 и GPU-вывода. Все шесть GPU-профилей с WB и ползунками проверены против существующей RGB-обработки с допуском 4/255 на канал.
- Тесты NV12 проверяют углы, плоскости Y/UV, масштабирование 2×2 → 4×4, ошибочные размеры/буферы и конкурентное использование кэша с разными размерами.
- Аппаратная проверка Samsung Note9 по USB проходит скрытие/возобновление предпросмотра, включение/выключение выходов, переходы RGB ↔ NV12 при изменении цвета/WB, поворот 90° и завершение декодеров. Новый APK установлен с сохранением подписи.
- Изображение с телефона проверено через существующий Spout2-источник OBS: положение нормальное. Трансформации источника без дополнительного переворота; временное включение скрытой группы для проверки возвращено в прежнее состояние. Эфир/запись не запускались.
- Android assembleRelease, JUnit и lintDebug завершены успешно. Windows собирается без предупреждений; unit-тесты проходят. Измерения AI-эффектов выполнялись отдельно от GPU-тестов, чтобы исключить конкуренцию тестов за ресурсы.

### Нагрузка USB 1080p60

Samsung Note9, HEVC 32 Мбит/с, новый NV12-путь, нейтральный цвет, Spout + виртуальная камера. ПК: 16 логических процессоров, RTX 4070 Ti. Обработчик предпросмотра намеренно задержан на 80 мс; основной вывод работает независимо.

| До нагрузки | 59,94 / 59,94 | 21,4% / 33,3% | 19,16 мс | 33,20 мс |

Ошибок декодирования и пропущенных GPU-загрузок — 0. Медленный предпросмотр выдавал около 10,7 FPS. Это синтетическая нагрузка без Hunt и активного эфира/записи. FPS публикации не измеряет полную задержку «объектив → монитор» или FPS рендера OBS. Проценты относятся ко всему ПК, поэтому не сравниваются напрямую с CPU самого клиента в [PERFORMANCE.md](PERFORMANCE.md).

## Повторение

Закройте рабочий клиент и помощник, который может его автоматически запускать. Сначала выполните сборку; тесты запускайте последовательно:

```powershell
dotnet build tests/S8Cam.Tests.csproj -c Release
dotnet run --project tests -c Release -- unit test-results
dotnet run --project tests -c Release -- gpu-video-test test-results/gpu-video
dotnet run --project tests -c Release -- shared-preview-test
dotnet run --project tests -c Release -- stress-test test-results/nv12-load 60 80 nv12
```

Последние две команды запускают камеру подключённого телефона по USB ADB и восстанавливают сохранённые настройки при завершении. GPU-тест использует локальное тестовое видео и не запускает камеру телефона. Изображения с телефона, пользовательские настройки и диагностические логи не включаются в публичные исходники/релиз.
